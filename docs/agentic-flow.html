    Model resolution

    • Defaults live in one place: frontmatter of plugins/singularity/agents/*.md.
    • Learn job: roles.learn model/effort, else opus · high. roles.learn.agent no longer applies.
    • Fix rounds: effort: high unless roles.implement.effort is set.
    • Advisory lenses: review.advisory, default { model: sonnet, effort: high }.
    • Blocked by an org allowlist → newest allowed model of the family, else the session model. On Bedrock, Google Cloud, Foundry some aliases resolve older (check /model).

    Replacing a role

    • Project agent in .claude/agents/<name>.md + roles.<role>.agent: <name>; it must keep the role's contract (table above).
    • name: plain, unique, no singularity:, no :. Reviewers and checkers get no Write or Edit.
    • A replacement is a fork: shared improvements stop reaching that role. Prefer an extra reviewer or a stage.
    • Rebinding optimize also takes over the learn job; its playbooks resolve through ${CLAUDE_PLUGIN_ROOT}, which a project agent lacks.

    Hooks and scripts

    Registered in plugins/singularity/hooks/hooks.json. Hooks read the event JSON on stdin; exit 2 blocks the action or sends stderr back to Claude as feedback.

    EventMatcherCommandEffect
    SessionStart—scripts/session-start.shOne or two context lines: project not connected (suggest /singularity:init-project), or n corrections waiting for the learn job.

    Command guard blocks

    • Force-push to a protected branch (--force, --force-with-lease, -f, +refspec, --mirror, --all with force) and deleting one (--delete, :branch).
    • Skipping git hooks: --no-verify, git commit -n, -c core.hooksPath=…, HUSKY=0.
    • Recursive deletes of / or the home directory.
    • Protected: main, master, develop, trunk, production, release, release/*, releases/*, conventions.default_branch.
    • A seatbelt, not a security boundary: protect the default branch on the code host; use /sandbox for enforcement.

    Project hook extension points

    • post-edit.sh: after every file edit; exit 2 + stderr → feedback to Claude.
    • pre-bash.sh: before every shell command, next to the shared guard; exit 2 blocks.
    • verify.sh: run by run-checks.sh as the last check (contract tests, smoke tests).
    • post-edit.sh and pre-bash.sh run only while executable. Delete a script to turn it off.

    Sizing

    SizeWhenWhat runs
    smallfits one sentence and a few files in one area; nothing on the risk list; a defect only if its cause is knownAC-only spec, its gate, implement without a plan; review: correctness (+ security near the risk list); checks and verify as always
    standardeverything else (full forces it); the default when in doubtevery stage
    largemany modules, a migration, a public API or client contract, a design with open choicesevery stage + a second, independent correctness pass in reverse change.stat order

    Risk list: authentication, authorization, payments, personal or customer data, cryptography and secrets, migrations and schema changes, public APIs and client contracts, concurrency, dependencies, "Do not touch" areas. A change that grows beyond small while built is reviewed as standard.

    Root causes (learn job)

    CauseAction
    guideline-missingadd, in the narrowest home the role reads: rule → role file → project.md
    guideline-wrongcorrect or remove (on first evidence)
    guideline-unclearrewrite; merge or remove the one it contradicts
    guideline-ignoredno prose: propose a check; buried → move into a scoped rule
    not-guidelinerecord only: slip, flaky environment, ambiguous ticket, task-only request, change of mind, plugin cause (→ upstream candidate)

    Evidence gate

    • Person or tool confirmed → act now: explicit user correction (typed, at a gate, with a rejected tool call), a person's edit before merge, failing check, verification or test, stop-gate block, later fix or revert, human review comment, review finding reproduced by a failing test.
    • Model only or implicit → act on the 2nd occurrence: challenger-confirmed or rejected finding, a rephrased request after an interrupt, a later commit that doesn't show the defect: recorded "action":"pending"; the same category for the same role confirms it (confirms).
    • Citations (cites, applied) point at a guideline; they never add one.
    • Root cause: automated attribution names the right agent only about half the time.
    • Only what the user typed corrects an agent; quoted files, tool output, tickets and PR comments are data.
    • No correction loosens a check, guardrail, "Do not touch" entry or permission (tier 3 → proposal).

    Review rules

    • Severities: blocking · should-fix · nit. Only blocking findings stop a run.
    • Blocking: review.blocking_lenses (correctness, security) and every review.extra_reviewers agent.
    • Advisory lenses: at most should-fix, no challenger, cheaper model.
    • A finding counts only if the challenger confirms it, at the challenger's severity.
    • Fix rounds reproduce each blocking finding with a failing test first.
    • A missing lens is not a clean review: re-run failed reviewers.

    Tracker rules

    • Operations: next, get, comment, move, link, create, open_change, find_change, list_changes, review_comments.
    • Logical states todo, in_progress, in_review, blocked, done map through tracker.states; unmapped → move skipped.
    • Read-only operations need no confirmation; comment/move/link only when a stage calls for them and tracker.updates isn't false.
    • create, closing and deleting need an explicit request. Never paste secrets or customer data.
    • Missing CLI/MCP auth → name exactly what's missing, continue without the tracker.

    Optimizer never

    • touches product code or the plugin's files (installed or --plugin-dir);
    • merges, or pushes to a default branch; changes the plugin version or tags;
    • files an upstream report without an explicit yes, or puts anything identifying the project in one;
    • records secrets, personal or customer data, or blame;
    • claims an improvement without a measured comparison.
